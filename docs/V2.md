# SOL BEAST 2.0

SOL BEAST 2.0 is a safety-first Solana keeper/MEV engine. It watches configured
liquidity pools, prices closed arbitrage cycles locally, simulates the resulting
Jito bundle, and only submits when every modelled cost is covered. The original
pump.fun sniper remains available as the legacy root binary; see
[LEGACY.md](LEGACY.md).

The rule is simple: **a live bundle must be profitable after swap fees, ATA
rent, the Jito tip and transaction fees, or it must revert on-chain.**

## What works today

| Capability | Status |
|---|---|
| Local Radar over configured pools | Working |
| 8 locally modelled AMM/pool families | Working |
| 3 locally decoded pool families | Working |
| 60-program venue registry (all mainnet-executable) | Working |
| Jupiter execution quotes and direct-route swaps | Working |
| Cost model, tip policy, risk caps, kill switch | Working |
| Jito bundle assembly, simulation and settlement | Working |
| Native on-chain profit guard | Source + host tests shipped; deploy required |
| Rent scanner and reclaimer | Working |
| Kamino flash loans (simulation-proven) | Working; no live bundle sent yet |
| HTTP API + token auth + CORS allowlist | Working |
| React dashboard | Working |
| Liquidation auctions / backrun / oracle-lag | **Not shipped** |
| Sandwiching, frontrunning, pool manipulation | **Never used** |

Live execution is gated behind **all** of the following:

1. `runtime.real = true` in config.
2. `--real` on the command line.
3. `runtime.mode = "live"` (or a strategy override that reaches live).
4. `jito.enabled = true` with a reachable block engine.
5. `guard.mode = "program"` with a deployed `guard.program_id`.
6. API signing is disabled unless the first five conditions are met.

If any gate is missing, the engine stays in Radar/Canary and only simulates.
`safety.allow_unguarded_live = true` deliberately removes gate 5 and must never
be treated as safe: without the guard there is no on-chain revert guarantee.

Flash cycles additionally keep the borrow and repayment in the same transaction.
WSOL flash cycles use the guard; non-WSOL cycles keep profit in the borrowed mint
and are reported with `lamport_guard = false`, because the lamport guard cannot
observe a token balance. Their protection is the enforced final minimum out and
the repayment instruction.

## Architecture

```
crates/
  beast-core     config, types, economics, risk, metrics
  beast-dex      venue registry, decoders, AMM math, router, Jupiter client
  beast-rpc      Solana JSON-RPC + Jito block-engine clients
  beast-store    SQLite persistence (pools, opportunities, attempts, bundles, settlements)
  beast-feed     websocket/HTTP pool feed + reserve refresh + decoders
  beast-flash    Kamino flash-loan adapter, reserve decoding and fee math
  beast-exec     quotes, transaction assembly, guard instruction, rent reclaimer
  beast-api      hardened axum API + optional static frontend
  beast-cli      `beast` command line and runtime loops
programs/guard   native Solana profit-guard program
frontend/        Vite + React dashboard
src/             legacy pump.fun sniper (`sol_beast` binary)
```

The workspace builds two binaries:

- `beast` — the v2 engine, API and tooling.
- `sol_beast` — the legacy pump.fun sniper.

## Quick start

### 1. Build and validate

```bash
cargo build --release -p beast-cli
cargo run --release -p beast-cli -- check
```

`beast check` validates configuration, guard gating and readiness without
network calls. It does not start the engine.

### 2. Create a config

```bash
cargo run --release -p beast-cli -- init
```

This writes `config.toml` and a `secrets.toml` with two distinct API tokens,
mode `0600`. The embedded defaults are used if `config.toml` is absent. Secrets
can also be supplied through `BEAST_SECRETS` or the environment variables
`BEAST_API_TOKEN` and `BEAST_API_READ_TOKEN`.

For the recommended zero-cost role split, copy the tracked
`config.v2.example.toml` instead and add `helius_api_key` / `alchemy_api_key` to
`secrets.toml`. See [RPC.md](RPC.md).

### 3. Discover pools

Radar needs pools. Discover them per venue and persist them:

```bash
# Example: Raydium CPMM. Use a dedicated RPC for getProgramAccounts.
cargo run --release -p beast-cli -- discover --venue raydium_cpmm --limit 50 --save

# Inspect the registry and coverage levels.
cargo run --release -p beast-cli -- venues
```

Only venues with a local decoder can be discovered. Quote-only venues are still
available to Jupiter at execution time. Full `getProgramAccounts` scans can be
heavy; the Helius free tier handles filtered scans such as the 630-reserve KLend
scan, or add individual pools through the dashboard/API.

### 4. Run the engine

```bash
# Radar: refresh pools, price routes, persist opportunities, never send.
cargo run --release -p beast-cli -- run

# Canary: build and simulate bundles, still never send.
#   Set runtime.mode = "canary" or a strategy mode = "canary".
```

Live mode needs the guard and Jito:

```bash
cargo run --release -p beast-cli -- run --real
```

### 5. Frontend

Development:

```bash
cd frontend
npm ci
npm run dev
```

The dev server proxies `/v1`, `/healthz` and `/readyz` to `127.0.0.1:8081`. Open
`http://localhost:3000` and log in with the admin token from `secrets.toml`.

Production (single process):

```bash
cd frontend
npm ci
npm run build
# config.toml:
# [api]
# static_dir = "frontend/dist"
cd ..
cargo run --release -p beast-cli -- run
```

Open `http://127.0.0.1:8081`. The API serves the SPA with a fallback while
keeping unknown `/v1/*` paths as 404.

## Venue coverage

The registry contains 60 Solana programs. At the time of writing
(2026-10-26), every registry program ID was checked with mainnet
`getMultipleAccounts` and was executable.

| Coverage | Count | Meaning |
|---|---:|---|
| `modeled` | 8 | Local reserves + AMM math. Radar can price these without Jupiter. |
| `decoded` | 3 | Local account decoder; reserves are verified before use. |
| `stake_pool` | 2 | Liquid-staking rate source for LST routes. |
| `quote_only` | 40 | Routed through Jupiter; no unverified local instruction builder. |
| `catalogued` | 6 | Program is known but has no shipped adapter and never routes locally. |
| `disabled` | 1 | Archived/deprecated program. Never routed. |

Modelled families: Raydium CPMM, Raydium AMM v4, PumpSwap, Meteora DAMM v2,
SPL Token Swap, Saber Stable, Orca Whirlpool, Raydium CLMM.

Decoded families: Meteora DLMM, Meteora DAMM v1, Sanctum Socean.

The registry is a catalogue, not a claim that every program can be scanned or
executed locally. `quote_only` venues are reached through Jupiter; `catalogued`
and `disabled` venues are deliberately non-executable.

## Strategies

Only strategies with working detectors and execution paths are shipped:

| Strategy | What it detects | Default mode |
|---|---|---|
| `cross_dex_arb` | Same-mint dislocation across two venues | Radar |
| `triangular_arb` | Three-leg cycle returning to the start mint | Off |
| `lst_arb` | LST redemption/secondary-market spread | Radar |
| `stable_arb` | Stable/correlated-asset pool spread | Off |
| `flash_arb` | Closed cycle funded by a Kamino flash loan | Off |
| `rent_reclaim` | Empty SPL token accounts that can be closed | Radar |

Every route is closed: the end mint must equal the start mint. Capital-funded
routes start and end at WSOL and are capped at 3 legs because Jito caps a
bundle at 5 transactions. `triangular_arb` and `flash_arb` are composed into a
single v0 transaction instead, so they can carry more than 3 Jupiter legs plus a
guard and tip. A flash route may start at any mint with an active Kamino reserve.

Not shipped, and not presented as adapters: liquidation auctions, backrunning,
oracle-lag trading, sandwiching, and pool manipulation. Flash borrowing is only
enabled for Kamino; every other provider is listed as unverified in
[FLASH_LOANS.md](FLASH_LOANS.md).

### Flash loans

```toml
[flash]
enabled = true
provider = "kamino"
mint = ""              # empty = deepest active reserve per mint
reserve = ""           # empty = discover; or pin one reserve
max_borrow_lamports = 1000000000

[strategies.flash_arb]
mode = "radar"
```

`flash_arb` cannot be armed while `[flash]` is disabled. Only `kamino` is an
accepted provider id. The borrow, Jupiter swaps and repayment share one
transaction, and the final minimum out must cover principal + reserve fee +
minimum profit + all lamport costs. At startup the engine either decodes a
pinned reserve, discovers reserves for one mint, or with both fields empty
loads the deepest active reserve for every Kamino mint.

The reserve fee is a 2<sup>60</sup> fixed-point fraction. Kamino's main-market
WSOL reserve charges exactly 10 ppm, so borrowing 1 SOL costs 10,000 lamports.
Fees are charged in the borrowed token; for non-WSOL cycles the engine converts
profit and fee to lamports through a Jupiter price before comparing them with
transaction costs. See [FLASH_LOANS.md](FLASH_LOANS.md) for the verified account
layout, fee arithmetic and proven limits.

## Execution and the profit guard

For a live opportunity the executor:

1. Verifies the route is closed; capital-funded routes must start and end at
   WSOL, flash routes at a mint with a loaded reserve, and no route exceeds 3
   legs.
2. Checks the wallet can fund the input (or the SOL-denominated costs for a
   flash cycle) plus `risk.balance_floor_lamports`.
3. Requests direct Jupiter quotes and requires each `minOut > 0`.
4. Requires the quoted cycle output to exceed the input.
5. Computes the worst-case cost: base fees for the actual transaction shape,
   intermediate ATA rent, the Jito tip and, for flash cycles, the reserve fee.
6. Refuses the route if the tip floor, minimum profit, fees or rent cannot be
   covered.
7. Builds one signed transaction per leg plus a guard and tip transaction, or
   one composed v0 transaction plus guard and tip for longer/flash cycles.
8. Simulates the bundle through Jito before submitting.
9. Submits a Jito bundle and polls status.
10. Reconciles settlements from real on-chain pre/post balance deltas.

A flash cycle has this shape:

```text
compute budget
[create the borrowed mint's ATA when absent]
flash borrow                    <- borrow_instruction_index
Jupiter leg 1 ... leg N
flash repay (principal)
[close the ATA]                 <- WSOL only
```

The final Jupiter leg is re-quoted so its enforced on-chain minimum out covers
principal + fee + minimum profit + base fees + rent + Jito tip. `prepare_flash_cycle`
refuses a cycle whose start mint has no loaded reserve, whose amount exceeds the
configured ceiling or observed availability, or whose reserve is paused.

The guard program is deliberately small. Its instruction payload is:

```
version u8 | expected_start u64 | min_profit u64 | tip u64 | remaining_fee u64
```

It reads the wallet's live lamport balance and aborts unless:

```
final_lamports >= expected_start + min_profit + tip + remaining_fee
```

`remaining_fee` is the tip transaction fee, which is still to be paid after the
guard. Swap fees and ATA rent have already left the wallet by the time the guard
runs, so they are **not** subtracted twice. The guard also rejects zero
`expected_start` and requires the wallet to remain above rent-exemption.

### Deploying the guard

The repository does not ship a fixed program ID. Generate one at deploy time:

```bash
solana-keygen new -o programs/guard/guard-keypair.json
solana address -k programs/guard/guard-keypair.json
cd programs/guard
cargo build-sbf
solana program deploy \
  --url <rpc> \
  --keypair <payer-keypair> \
  --program-id guard-keypair.json \
  target/deploy/beast_guard.so
```

Then set:

```toml
[guard]
enabled = true
mode = "program"
program_id = "<deployed program id>"
```

The guard has no admin, upgrade authority, or token accounts. Treat the deploy
keypair as sensitive and remove it from the machine after deployment.

### Bundle atomicity caveat

Jito bundles execute atomically in normal operation, and the guard/revert rule
protects the bundle. Jito documents that uncled blocks can be re-proposed by
validators and individual transactions can land without the rest of the bundle.
That is a protocol-level residual risk for any separate-transaction bundle. The
engine does not claim otherwise: live readiness must be validated on a fork and
with a small mainnet bundle, and the settlement loop halts trading on a landed
negative net.

## Costs and profitability

The engine accounts for:

- Base fee per bundle transaction (default 5,000 lamports).
- Intermediate associated-token-account rent, retained after a successful cycle.
- Jito tip, bounded by `tip_alpha` and `max_tip_lamports`, with a 1,000-lamport
  floor.
- The flash reserve fee, converted to lamports when the borrowed mint is not
  WSOL.
- The configured minimum profit.

`min_net_lamports` is checked again after the cost model. A route is dropped if
it cannot cover all costs and the minimum. Settlement compares the model against
actual on-chain deltas and records model error.

## HTTP API

Bind defaults to `127.0.0.1:8081`. Remote binding is rejected unless
`api.allow_remote = true` and `api.allowed_origins` is non-empty.

Authentication uses two distinct tokens:

- Admin token: `Authorization: Bearer <api_bearer_token>` or `x-api-token`.
- Read token: same headers, read-only routes only.

Read routes:

```
GET /healthz                 public liveness
GET /readyz                  public readiness
GET /v1/status
GET /v1/dashboard
GET /v1/config               redacted
GET /v1/venues
GET /v1/pools
GET /v1/opportunities
GET /v1/attempts
GET /v1/bundles
GET /v1/settlements
GET /v1/report
GET /v1/rent
GET /v1/events
GET /v1/strategies
GET /v1/metrics              Prometheus text
POST /v1/quote
```

Admin routes:

```
POST   /v1/mode
POST   /v1/kill
POST   /v1/resume
POST   /v1/strategies/:name
POST   /v1/feed/refresh
POST   /v1/pools
DELETE /v1/pools/:address
POST   /v1/rent/reclaim
```

`/v1/quote` is read-token authenticated but performs an upstream Jupiter call.
Pool additions validate the venue against the registry. Signing endpoints are
only enabled when live gates are satisfied; otherwise they return `403`.
`/v1/status` and `/v1/dashboard` include the flash provider, the deepest reserve,
its fee and the number of borrowable mints (`flash: null` when disabled).

## Rent reclaimer

`beast rent` scans the wallet's own token accounts and closes only accounts
that are initialized, have zero token balance, and are owned by the wallet. It
does not burn dust and does not touch accounts with a balance. `--real
--confirm` is required to send; without both flags it is a dry run.

The dashboard's Rent page uses the same scanner and requires the admin token to
send.

## Risk controls

- `risk.balance_floor_lamports`: wallet reserve that must remain untouched.
- `risk.max_inflight_bundles` / `max_inflight_per_strategy`: caps.
- `risk.max_attempts_per_min`: attempt rate cap.
- `risk.daily_landed_cost_cap_lamports`: daily paid-cost cap.
- `risk.max_consecutive_failures`: automatic halt.
- `risk.max_model_error_bps`: model-vs-realized error cap.
- `risk.max_feed_lag_ms` / `max_slot_lag`: stale-data guards.
- `risk.kill_switch_file`: file-triggered kill switch (default `./STOP`).
- API `kill`/`resume` and strategy mode changes.

A negative landed net is treated as a guard violation: metrics increment, an
error event is written, and the risk engine halts.

## Known limits and gates

These are not hidden behind UI labels; they are excluded from the shipped
strategy set or require operator action:

1. **Guard deployment**: the SBF build and mainnet deployment are environment
   dependent and must be performed by the operator.
2. **Mainnet bundle validation**: Jito behaviour, tip floors and landing rates
   must be validated with a small live bundle before scaling.
3. **Flash: simulation only so far**: the Kamino borrow → repay round trip is
   proven on mainnet by simulation, but no live flash bundle has been sent.
   Landing additionally depends on Jito, compute budget and wallet balance.
4. **Flash: one verified provider**: only Kamino is enabled. Solend/Save,
   Marginfi, Drift, Port and Larix remain unverified and cannot be selected.
5. **Flash: non-WSOL cycles have no lamport guard**: profit stays in the
   borrowed token, so the separate guard is omitted. Protection is the enforced
   final minimum out plus the repayment instruction.
6. **Flash: availability changes**: a reserve can be paused, drained or re-priced
   between planning and landing. The executor re-reads the reserve before
   building, and the repay instruction is the final on-chain check.
7. **No liquidation/backrun/oracle-lag**: removed from code, config and UI.
8. **Pool discovery is manual/per-venue**: the engine does not crawl every pool
   on every program at startup.
9. **Quote-only venues are not locally modelled**: they can appear in Jupiter
   execution routes, but Radar cannot price them without a local model.
10. **Uncled-block unbundling**: see the bundle caveat above.
11. **No live mainnet results are claimed** by this repository. Settlement data
    is only meaningful after the operator runs a live bundle.

The legacy pump.fun sniper is historically separate and is not part of the v2
profitability guarantee.
